# 午餐选择器

一个基于 HarmonyOS / ArkTS / ArkUI 开发的午餐决策工具。它不是简单地“随机一下”，而是围绕真实午餐场景加入了候选管理、标签筛选、确认机制、历史统计、本地持久化、近期去重降权和多端自适应布局，让“今天中午吃什么”这件小事更快做决定。

![午餐选择器功能介绍](./screenshots/lunch-picker-features.png)

## 项目亮点

- **少纠结**：最多允许换 3 次推荐，第 3 次会自动确认当前结果，避免无限刷新。
- **结果更实用**：支持标签筛选，只在当前想吃的类型里推荐。
- **历史更准确**：随机结果不会立即写入历史，只有确认“就吃这个”后才记录。
- **长期可用**：候选项、标签和历史记录会通过 HarmonyOS Preferences 保存在本地。
- **多端适配**：同一套 entry 模块支持 phone、tablet 和 2in1，页面会根据窗口宽度在单列和双栏之间切换。
- **界面更聚焦**：首页优先展示推荐结果、标签和候选列表，添加、历史、管理等低频功能默认折叠，宽屏下同时展示决策区和管理区。

## 功能介绍

### 午餐推荐

- 点击“帮我决定”生成一个待确认推荐。
- 推荐后可以选择“就吃这个”或“换一个”。
- 每轮最多换 3 次，第 3 次换出的结果会自动确认。
- 确认后的结果会进入历史记录，并参与后续统计与降权。

### 候选项管理

- 支持添加新的午餐候选项。
- 支持为每个候选项添加多个标签。
- 支持删除不想参与推荐的候选项。
- 支持一键恢复默认候选项。
- 至少保留 1 个候选项，避免列表为空导致无法推荐。

默认候选项包括：

- 黄焖鸡
- 兰州拉面
- 牛肉饭
- 轻食沙拉
- 馄饨
- 麻辣烫

### 标签筛选

候选项可以带有多个标签，例如：

- 米饭
- 面食
- 汤类
- 轻食
- 重口
- 清淡
- 快餐
- 外卖
- 健康

用户可以先选择标签，再点击推荐。比如只想吃“面食”，系统就只会在带有“面食”标签的候选项中推荐。

标签输入支持中文逗号、英文逗号、顿号和空格分隔：

```text
米饭 重口 外卖
```

```text
米饭，重口，外卖
```

### 推荐确认机制

这是当前版本的核心体验优化。

传统随机工具通常点一次就直接记录结果，容易出现误点、乱刷、统计不准的问题。本项目改成了两步：

1. 先生成“待确认推荐”。
2. 用户确认后才写入历史记录。

如果用户一直点“换一个”，程序会在第 3 次换完后自动确认当前结果。这个设计符合项目目标：帮助用户做决定，而不是制造新的选择困难。

### 智能随机策略

推荐逻辑不是完全平均随机，而是加入了简单的日常决策优化：

- 最近 2 次确认吃过的午餐会优先避让。
- 最近 5 次中出现频率较高的午餐会降低权重。
- 开启标签筛选后，只在筛选结果内推荐。

这样可以减少连续几天吃到同一种午餐的概率。

### 历史记录与统计

应用会记录最近确认过的午餐结果，包括名称和确认时间。

当前统计包括：

- 总确认次数
- 最近常吃
- 很久没吃

统计只基于确认后的结果，不会被未确认的随机推荐污染。

### 本地持久化

项目使用 HarmonyOS Preferences 保存轻量数据：

- 午餐候选项
- 候选项标签
- 历史记录

关闭应用后重新打开，已添加的候选项和历史数据仍会保留。

## 界面设计

当前界面以“快速决策”为核心：

- 首屏突出“今天吃什么”和推荐按钮。
- 标签筛选紧跟推荐区，便于先筛选再决策。
- 候选列表显示当前可选项和命中结果。
- 添加午餐、最近结果、管理操作默认折叠，减少视觉干扰。
- 整体采用暖色、轻量卡片和紧凑排版，适合日常高频使用。

## 多端部署与一多适配

本项目按一次开发多端部署思路完成了三层适配：

- **工程级一多**：`entry/src/main/module.json5` 中的 `deviceTypes` 已声明 `phone`、`tablet`、`2in1`，同一 HAP 可面向多类设备安装运行。
- **功能级一多**：候选管理、标签筛选、随机推荐、历史统计和 Preferences 本地存储都在同一套 ViewModel 与存储封装中复用，不为不同设备拆分重复业务代码。
- **界面级一多**：`LunchPickerPage.ets` 根据窗口宽度切换布局。窄屏使用单列滚动布局，适合手机快速决策；宽屏使用双栏布局，左侧展示推荐和筛选，右侧展示候选列表和工具面板，更适合平板和 2in1。

当前断点策略：

- 小于 `720vp`：手机单栏布局。
- 大于等于 `720vp`：平板双栏布局。
- 大于等于 `1080vp`：2in1 / 桌面场景限制最大内容宽度，避免内容被拉得过散。

## 自由流转 / 应用接续

当前版本支持 HarmonyOS 自由流转中的应用接续场景：用户可以在一台设备上开始午餐决策，再把当前决策状态继续到另一台设备上。

会随接续传递的状态包括：

- 当前页面标识、标签筛选、添加午餐输入草稿和标签草稿。
- 当前推荐结果、待确认状态、已换次数和三个折叠面板的展开状态。
- 裁剪后的候选午餐列表和最近历史记录。

不会随接续直接写入本地持久化的数据包括：

- 目标设备上的 Preferences 不会在页面恢复时立刻被覆盖。
- 接续状态只作为临时页面状态恢复；只有用户在目标设备继续添加、删除、确认或清空后，才会按原有逻辑写入 Preferences。

手动测试步骤：

1. 在设备 A 上选择一个标签。
2. 点击“帮我决定”生成推荐，再点一次“换一个”。
3. 展开“添加午餐”，输入一个新的候选名称和标签，但先不要添加。
4. 发起自由流转到设备 B。
5. 检查设备 B 是否恢复标签、待确认结果、已换次数、输入草稿、面板状态、候选项和历史记录。
6. 在设备 B 点击“就吃这个”，确认历史记录正常更新。

限制说明：

- 接续数据走 Want 参数，已做裁剪：候选项最多传递 30 个，历史记录最多传递 20 条。
- 接续状态会校验页面标识、换一换次数、候选项名称、标签数组、历史记录和当前选中项；校验失败时会忽略接续数据并走普通启动流程。
- 当前实现传递的是轻量页面状态，不传递图片、网络请求上下文或未落盘的系统级资源。

## 工程结构

```text
Lunch_chooser
├── AppScope
│   └── app.json5
├── entry
│   └── src/main
│       ├── ets
│       │   ├── entryability
│       │   │   └── EntryAbility.ts
│       │   ├── pages
│       │   │   └── LunchPickerPage.ets
│       │   ├── viewmodel
│       │   │   ├── LunchPickerViewModel.ets
│       │   │   ├── LunchHistoryItem.ets
│       │   │   └── LunchContinuationState.ts
│       │   └── common/utils
│       │       └── LunchStorage.ets
│       └── resources
│           └── base/profile/main_pages.json
├── build-profile.json5
└── oh-package.json5
```

核心文件说明：

- `EntryAbility.ts`：应用入口，加载午餐选择器页面。
- `LunchPickerPage.ets`：主页面 UI 和交互逻辑。
- `LunchPickerViewModel.ets`：候选项模型、标签处理、筛选、随机策略和统计逻辑。
- `LunchHistoryItem.ets`：历史记录数据结构。
- `LunchContinuationState.ts`：自由流转接续状态模型、裁剪和校验逻辑。
- `LunchStorage.ets`：Preferences 本地持久化封装。
- `main_pages.json`：页面注册，目前只注册午餐选择器主页面。

## 运行环境

- 设备类型：phone / tablet / 2in1
- HarmonyOS：5.0.5 Release 及以上
- DevEco Studio：6.0.2 Release 及以上
- HarmonyOS SDK：6.0.2 Release SDK 及以上
- Runtime OS：HarmonyOS

## 如何运行

1. 使用 DevEco Studio 打开 `Lunch_chooser` 工程。
2. 等待工程同步完成。
3. 选择可用的 HarmonyOS 模拟器或真机。
4. 运行 `entry` 模块。

如果本地构建时出现类似提示：

```text
Will skip sign 'hos_hap'. No signingConfigs profile is configured...
```

这是签名配置提醒，通常不影响本地开发调试。正式发布前需要在 `build-profile.json5` 中补充签名配置。
